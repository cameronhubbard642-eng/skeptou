## §I — Purpose + scope

### §I.1 — What strategia is

`strategia.skeptou.com` (Slot 8) is a read-oriented document archive and in-app viewer for reports and documents generated by Claude. It is **not** a general-purpose file store and **not** an editing surface. Its function is receipt and display.

Documents that belong in strategia:

| Document class | Examples | Format |
|---|---|---|
| CoC session briefs | Committee of Correspondence session summaries | Markdown |
| Annotated PDFs | Copy-editing passes, review PDFs with highlights | PDF |
| Worksheets | Planning worksheets, rubrics, grading guides | Markdown or PDF |
| Generic reports | Any structured Claude-generated report from a team | Markdown |
| Future formats | Images, diagrams (Phase 3+) | TBD |

Documents that do **not** belong in strategia:

- O&P structured data (projects, tasks, opportunities) — that is phronesis / D1
- Working drafts and papers under active revision — that is energeia
- Teaching materials — that is paideia
- Professional documents (CVs, letters) — that is aristeia

### §I.2 — Design posture

Strategia is intentionally minimal on the write side. The primary actors writing to it are Claude team specialists (via service token) and, optionally, Cam (via admin upload form). The primary actor reading from it is Cam, via the browser UI. There is no collaboration surface, no commenting, no versioning. A document arrives, is viewable in-app, and can be deleted by Cam. That is the complete interaction model.

**Read without downloading** is the defining UX constraint. Cam should be able to open and read any document without the browser forcing a file download. This is achieved by policy (no download UI) and by implementation choice (in-app renderer for each supported MIME type).

## §II — Architecture overview

```
strategia.skeptou.com/*          ← Cloudflare Pages (static UI shell)
  /                              ← Document list / index
  /view/:slug                    ← In-app viewer route

strategia.skeptou.com/api/*      ← Cloudflare Worker (strategia-worker)
  GET    /api/documents          ← List (filters: team, content_type, date range)
  GET    /api/documents/:slug    ← Metadata
  GET    /api/documents/:slug/content  ← Stream R2 object
  POST   /api/documents          ← Upload (multipart; session or Bearer service token)
  DELETE /api/documents/:slug    ← Hard delete (session only; Cam actor)
```

**Storage:**

```
R2 (skeptou-strategia)           ← Document bytes
D1 (skeptou-strategia)           ← Document metadata, audit log
```

**Auth layer:** `@skeptou/auth-client` (auth-core). Same session-cookie + service-token dual path as phronesis (see `specs/auth-core.md`). Cloudflare Access gate covers `strategia.skeptou.com/*`; Worker adds its own `authenticateRequest()` check on `/api/*`.

**Worker bindings (wrangler.toml):**

```toml
[[r2_buckets]]
binding = "STRATEGIA_R2"
bucket_name = "skeptou-strategia"

[[d1_databases]]
binding = "STRATEGIA_DB"
database_name = "skeptou-strategia"
database_id = "<uuid>"
```

## §III — Storage architecture

### §III.1 — Why R2 + D1

PDFs and markdown blobs can be arbitrarily large. D1 (SQLite) is a relational store suited to structured rows, not binary blobs. R2 is Cloudflare's object store — suited to arbitrary byte payloads, no egress fees within the Cloudflare network, and directly streamable to the browser via a Worker `Response` wrapping the R2 object body.

D1 holds the **metadata envelope** for each document: enough information to list, filter, and describe documents without fetching the R2 object. The R2 object is fetched only when Cam navigates to the viewer route for a specific document.

### §III.2 — R2 object key schema

```
<source_team>/<slug>.<ext>
```

Examples:
```
coc/brief-2026-05-14-session-12.md
coc/annotated-draft-ch3-2026-05-10.pdf
saa/worksheet-dissertation-planning-2026-04-20.md
phronesis-engineer/report-phase1-qa-2026-03-01.md
```

`source_team` is the token-scope prefix assigned to each specialist or team (§X.2). It is also embedded in the D1 row for filtering. This means:

- A scoped service token can only write objects under its own prefix
- List operations can be prefix-filtered in D1 without an R2 list call

### §III.3 — R2 operational notes

- Objects are stored with the `Content-Type` MIME header matching the uploaded document (enforced at upload time by the Worker)
- No expiry or lifecycle policy on R2 objects in Phase 1. Phase 3+ may add archival lifecycle rules.
- R2 egress from Worker to browser is free within Cloudflare. Object storage cost is negligible at this volume.
- On hard delete (§VIII), the R2 object is deleted synchronously in the same Worker request as the D1 row deletion.

### §IV.2 — `0001_initial_schema.sql`

```sql
-- ============================================================
-- Strategia document metadata — skeptou-strategia D1 database
-- Sképtou / specs/strategia.md rev 1
-- ============================================================

CREATE TABLE IF NOT EXISTS documents (
  slug            TEXT    PRIMARY KEY,
  title           TEXT    NOT NULL,
  source_team     TEXT    NOT NULL,         -- e.g. 'coc', 'saa', 'cam'
  source_actor    TEXT    NOT NULL,         -- specialist name or 'cam'
  content_type    TEXT    NOT NULL
                          CHECK (content_type IN ('brief','annotated_pdf','worksheet','report','image','other')),
  mime_type       TEXT    NOT NULL,         -- e.g. 'application/pdf', 'text/markdown'
  r2_key          TEXT    NOT NULL UNIQUE,  -- full R2 object key (team/slug.ext)
  byte_size       INTEGER NOT NULL,
  created_at      TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  deleted_at      TEXT,                     -- NULL = live; populated on hard delete (tombstone)
  tags            TEXT    NOT NULL DEFAULT '[]',  -- JSON array of strings
  metadata        TEXT    NOT NULL DEFAULT '{}'   -- arbitrary JSON for future extension
);

-- Trigger: prevent updates to immutable fields
CREATE TRIGGER IF NOT EXISTS documents_no_update
  BEFORE UPDATE ON documents
  FOR EACH ROW
  WHEN NEW.slug != OLD.slug
    OR NEW.r2_key != OLD.r2_key
    OR NEW.created_at != OLD.created_at
BEGIN
  SELECT RAISE(ABORT, 'slug, r2_key, and created_at are immutable');
END;

CREATE TABLE IF NOT EXISTS audit_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  table_name    TEXT    NOT NULL DEFAULT 'documents',
  row_key       TEXT    NOT NULL,           -- document slug
  action        TEXT    NOT NULL CHECK (action IN ('INSERT','DELETE')),
  actor         TEXT    NOT NULL,
  snapshot      TEXT    NOT NULL DEFAULT '{}',  -- JSON snapshot of row at time of action
  occurred_at   TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
```

**Design notes:**

- `deleted_at` — documents are never physically removed from D1 (the row is retained as a tombstone with `deleted_at` set). The R2 object **is** deleted immediately on `DELETE /api/documents/:slug`. This gives auditability (who deleted what, when) while freeing storage.
- `tags` — JSON array stored as TEXT (D1/SQLite does not have a native array type). Queried via `json_each()` in filtered list queries.
- `content_type` is a controlled vocabulary for UI filtering and icon rendering; `mime_type` is the actual HTTP Content-Type for browser rendering.
- `metadata` is an escape hatch for future fields (e.g. page count, word count, associated project slug) without a schema migration.
- No `updated_at` — documents are immutable once uploaded (title, source, r2_key cannot change). The only mutation is deletion.

### §IV.4 — Live documents view

```sql
CREATE VIEW IF NOT EXISTS live_documents AS
  SELECT * FROM documents WHERE deleted_at IS NULL;
```

All read API endpoints query `live_documents`, not `documents` directly. This ensures deleted documents are invisible without conditional WHERE clauses in every handler.

## §V — API surface

### §V.1 — `GET /api/documents`

List live documents. Supports filter parameters.

**Query parameters:**

| Param | Type | Description |
|---|---|---|
| `team` | string | Filter by `source_team` |
| `content_type` | string | Filter by content_type enum value |
| `since` | ISO 8601 | Filter by `created_at >= since` |
| `until` | ISO 8601 | Filter by `created_at <= until` |
| `tag` | string | Filter documents whose `tags` array contains this value |
| `limit` | integer | Max results (default 50, max 200) |
| `offset` | integer | Pagination offset (default 0) |

**Auth:** session cookie or Bearer service token (any scope).

**Response `200`:**
```json
{
  "data": [
    {
      "slug": "brief-2026-05-14-session-12",
      "title": "CoC Session 12 Brief — 2026-05-14",
      "source_team": "coc",
      "source_actor": "coc-scribe",
      "content_type": "brief",
      "mime_type": "text/markdown",
      "byte_size": 4821,
      "created_at": "2026-05-14T18:23:11Z",
      "tags": ["coc", "session-12"]
    }
  ],
  "meta": {
    "total": 47,
    "limit": 50,
    "offset": 0
  }
}
```

Note: `r2_key` and `metadata` are **not** returned in list responses. They are returned only in `GET /api/documents/:slug`.

**Handler sketch:**

```typescript
async function listDocuments(request: Request, env: Env): Promise<Response> {
  const url = new URL(request.url);
  const params = {
    team:         url.searchParams.get('team'),
    content_type: url.searchParams.get('content_type'),
    since:        url.searchParams.get('since'),
    until:        url.searchParams.get('until'),
    tag:          url.searchParams.get('tag'),
    limit:  Math.min(parseInt(url.searchParams.get('limit')  ?? '50'),  200),
    offset:       parseInt(url.searchParams.get('offset') ?? '0'),
  };

  let sql = `SELECT slug, title, source_team, source_actor, content_type, mime_type, byte_size, created_at, tags
             FROM live_documents WHERE 1=1`;
  const bindings: unknown[] = [];

  if (params.team)         { sql += ` AND source_team = ?`;    bindings.push(params.team); }
  if (params.content_type) { sql += ` AND content_type = ?`;   bindings.push(params.content_type); }
  if (params.since)        { sql += ` AND created_at >= ?`;    bindings.push(params.since); }
  if (params.until)        { sql += ` AND created_at <= ?`;    bindings.push(params.until); }
  if (params.tag)          {
    sql += ` AND EXISTS (SELECT 1 FROM json_each(tags) WHERE value = ?)`;
    bindings.push(params.tag);
  }

  const countSql = sql.replace(/SELECT .* FROM/, 'SELECT COUNT(*) as total FROM');
  sql += ` ORDER BY created_at DESC LIMIT ? OFFSET ?`;
  bindings.push(params.limit, params.offset);

  const [rows, countRow] = await env.STRATEGIA_DB.batch([
    env.STRATEGIA_DB.prepare(sql).bind(...bindings),
    env.STRATEGIA_DB.prepare(countSql).bind(...bindings.slice(0, -2)),
  ]);

  return Response.json({
    data: rows.results,
    meta: { total: (countRow.results[0] as { total: number }).total, limit: params.limit, offset: params.offset },
  });
}
```

### §V.3 — `GET /api/documents/:slug/content`

Stream the R2 object to the browser. This is the route the in-app viewer fetches.

**Auth:** session cookie or Bearer service token (any scope). Note: this route is also reachable via the Cloudflare Access gate, so the double-auth (Access + Worker auth) applies.

**Response:** R2 object body streamed with the original `Content-Type` header. Additional headers:

```
Content-Type: <mime_type from D1 row>
Content-Disposition: inline; filename="<slug>.<ext>"
X-Content-Type-Options: nosniff
Cache-Control: private, no-store
```

`Content-Disposition: inline` tells the browser to render rather than download. `no-store` prevents caching of sensitive document content at the browser layer.

**Handler sketch:**

```typescript
async function getDocumentContent(slug: string, env: Env): Promise<Response> {
  const row = await env.STRATEGIA_DB.prepare(
    `SELECT r2_key, mime_type, slug FROM live_documents WHERE slug = ?`
  ).bind(slug).first<{ r2_key: string; mime_type: string; slug: string }>();

  if (!row) return Response.json({ error: 'not found' }, { status: 404 });

  const object = await env.STRATEGIA_R2.get(row.r2_key);
  if (!object) return Response.json({ error: 'storage object missing' }, { status: 500 });

  const ext = row.r2_key.split('.').pop() ?? 'bin';

  return new Response(object.body, {
    headers: {
      'Content-Type':              row.mime_type,
      'Content-Disposition':       `inline; filename="${row.slug}.${ext}"`,
      'X-Content-Type-Options':    'nosniff',
      'Cache-Control':             'private, no-store',
    },
  });
}
```

### §V.4 — `POST /api/documents`

Upload a document. Accepts multipart form data.

**Auth:** session cookie (Cam actor) OR Bearer service token scoped to the uploading team.

**Request:** `Content-Type: multipart/form-data`

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | File | yes | Document binary |
| `slug` | string | yes | URL-safe unique identifier |
| `title` | string | yes | Human-readable title |
| `content_type` | string | yes | Enum: `brief`, `annotated_pdf`, `worksheet`, `report`, `image`, `other` |
| `tags` | string | no | Comma-separated or JSON array string |
| `metadata` | string | no | JSON object string |

**Slug validation:** `^[a-z0-9][a-z0-9\-]{2,127}$`. Must be unique; 409 if already exists.

**MIME type detection:** derived from the uploaded file's `Content-Type` header. Validated against an allowlist (§V.4.1). Rejected if not in allowlist.

**R2 key construction:** `<token_scope_prefix>/<slug>.<ext>` where `ext` is derived from MIME type. For session-auth uploads (Cam), `source_team` is `cam`.

**Atomicity:** D1 INSERT occurs only after R2 `put()` succeeds. If D1 INSERT fails after R2 put, the R2 object is orphaned (no rollback mechanism on R2). Mitigation: a nightly reconciliation script (Phase 3+) can detect orphaned R2 objects by comparing R2 list against D1 r2_key column.

**Response `201`:**
```json
{
  "data": {
    "slug": "brief-2026-05-14-session-12",
    "r2_key": "coc/brief-2026-05-14-session-12.md",
    "byte_size": 4821
  }
}
```

#### §V.4.1 — MIME type allowlist

```typescript
const ALLOWED_MIME_TYPES: Record<string, string> = {
  'application/pdf':                                 'pdf',
  'text/markdown':                                   'md',
  'text/plain':                                      'txt',
  'image/png':                                       'png',
  'image/jpeg':                                      'jpg',
  'image/webp':                                      'webp',
  // Future:
  // 'application/vnd.openxmlformats-officedocument.wordprocessingml.document': 'docx',
};
```

`.docx` is intentionally out of scope for Phase 1 (open question Q3). The handler returns `415 Unsupported Media Type` for unlisted MIME types.

**Handler sketch:**

```typescript
async function uploadDocument(request: Request, auth: AuthContext, env: Env): Promise<Response> {
  const formData  = await request.formData();
  const file      = formData.get('file') as File;
  const slug      = (formData.get('slug') as string)?.trim();
  const title     = (formData.get('title') as string)?.trim();
  const ctype     = (formData.get('content_type') as string)?.trim();
  const tagsRaw   = (formData.get('tags') as string) ?? '[]';
  const metaRaw   = (formData.get('metadata') as string) ?? '{}';

  // Validation
  if (!file || !slug || !title || !ctype) {
    return Response.json({ error: 'file, slug, title, content_type required' }, { status: 400 });
  }
  if (!/^[a-z0-9][a-z0-9\-]{2,127}$/.test(slug)) {
    return Response.json({ error: 'invalid slug format' }, { status: 400 });
  }
  const ext = ALLOWED_MIME_TYPES[file.type];
  if (!ext) return Response.json({ error: 'unsupported mime type' }, { status: 415 });

  // Scope prefix: from service token scope, or 'cam' for session auth
  const teamPrefix = auth.mode === 'service_token' ? auth.scope : 'cam';
  const r2Key      = `${teamPrefix}/${slug}.${ext}`;

  // Check slug uniqueness
  const existing = await env.STRATEGIA_DB.prepare(
    `SELECT slug FROM documents WHERE slug = ?`
  ).bind(slug).first();
  if (existing) return Response.json({ error: 'slug already exists' }, { status: 409 });

  // R2 write first
  const bytes = await file.arrayBuffer();
  await env.STRATEGIA_R2.put(r2Key, bytes, {
    httpMetadata: { contentType: file.type },
  });

  // D1 insert
  const tags     = Array.isArray(JSON.parse(tagsRaw)) ? tagsRaw : JSON.stringify([tagsRaw]);
  const now      = new Date().toISOString();
  await env.STRATEGIA_DB.batch([
    env.STRATEGIA_DB.prepare(
      `INSERT INTO documents (slug, title, source_team, source_actor, content_type, mime_type, r2_key, byte_size, tags, metadata)
       VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`
    ).bind(slug, title, teamPrefix, auth.actor, ctype, file.type, r2Key, bytes.byteLength, tags, metaRaw),
    env.STRATEGIA_DB.prepare(
      `INSERT INTO audit_log (row_key, action, actor, snapshot) VALUES (?, 'INSERT', ?, ?)`
    ).bind(slug, auth.actor, JSON.stringify({ slug, title, source_team: teamPrefix, r2_key: r2Key })),
  ]);

  return Response.json({ data: { slug, r2_key: r2Key, byte_size: bytes.byteLength } }, { status: 201 });
}
```

### §V.5 — `DELETE /api/documents/:slug`

Hard delete. Cam-only operation.

**Auth:** session cookie only. Bearer service tokens are **rejected** regardless of scope (see §VIII).

**Behavior:**
1. Fetch D1 row from `live_documents` — 404 if missing or already deleted
2. Write `audit_log` row (snapshot of document before deletion) via D1 batch
3. Mark `deleted_at = now()` on the D1 row (tombstone — row retained for audit)
4. Delete R2 object at `row.r2_key`
5. Return `204 No Content`

**Response `204`:** no body.
**Response `403`:** service-token attempt (actor is not `cam` session).
**Response `404`:** document not found or already deleted.

**Handler sketch:**

```typescript
async function deleteDocument(slug: string, auth: AuthContext, env: Env): Promise<Response> {
  // Cam-session gate
  if (auth.mode !== 'session' || auth.actor !== 'cam') {
    return Response.json({ error: 'delete requires Cam session' }, { status: 403 });
  }

  const row = await env.STRATEGIA_DB.prepare(
    `SELECT slug, title, r2_key, source_team, source_actor FROM live_documents WHERE slug = ?`
  ).bind(slug).first<{ slug: string; title: string; r2_key: string; source_team: string; source_actor: string }>();

  if (!row) return Response.json({ error: 'not found' }, { status: 404 });

  const now = new Date().toISOString();

  // Write tombstone + audit in one batch
  await env.STRATEGIA_DB.batch([
    env.STRATEGIA_DB.prepare(
      `UPDATE documents SET deleted_at = ? WHERE slug = ?`
    ).bind(now, slug),
    env.STRATEGIA_DB.prepare(
      `INSERT INTO audit_log (row_key, action, actor, snapshot) VALUES (?, 'DELETE', ?, ?)`
    ).bind(slug, auth.actor, JSON.stringify(row)),
  ]);

  // Purge R2 object
  await env.STRATEGIA_R2.delete(row.r2_key);

  return new Response(null, { status: 204 });
}
```

## §VI — In-app viewer

### §VI.1 — Rendering strategy by MIME type

| MIME type | Renderer | Notes |
|---|---|---|
| `application/pdf` | **PDF.js** | Recommended over `<iframe>` — see §VI.2 |
| `text/markdown` | `marked.js` + DOMPurify sanitize | Client-side render |
| `text/plain` | `<pre>` block | No library needed |
| `image/png`, `image/jpeg`, `image/webp` | `<img src="/api/documents/:slug/content">` | Direct R2 stream |
| Unsupported | "Preview unavailable" stub + optional download | Policy fallback only |

### §VI.2 — PDF.js recommendation

Recommendation: **PDF.js** (Mozilla), loaded from CDN or bundled.

Rationale over `<iframe>` embedding:

| Factor | PDF.js | `<iframe>` native |
|---|---|---|
| Download bar | None — full UI control | Browser renders native toolbar with download button |
| Rendering consistency | Uniform across browsers (JS renderer) | Safari, Chrome, Firefox differ |
| Annotation / search | Can expose search; can suppress download button entirely | Cannot suppress native controls |
| Custom styling | Full — can apply Borges aesthetic to PDF chrome | None |
| Mobile behaviour | Controlled scrolling | Often broken on iOS Safari |

PDF.js fetches the document from `/api/documents/:slug/content` (authenticated fetch using the session cookie the browser already holds). The streamed response with `Content-Disposition: inline` combined with PDF.js rendering means the browser never triggers its native PDF handler.

**Minimal integration:**

```html
<!-- In the /view/:slug route -->
<div id="pdf-container"></div>
<script src="https://cdnjs.cloudflare.com/ajax/libs/pdf.js/4.2.67/pdf.min.js"></script>
<script>
  pdfjsLib.GlobalWorkerOptions.workerSrc =
    'https://cdnjs.cloudflare.com/ajax/libs/pdf.js/4.2.67/pdf.worker.min.js';

  async function renderPDF(slug) {
    const res  = await fetch(`/api/documents/${slug}/content`, { credentials: 'include' });
    const buf  = await res.arrayBuffer();
    const pdf  = await pdfjsLib.getDocument({ data: buf }).promise;
    const container = document.getElementById('pdf-container');

    for (let i = 1; i <= pdf.numPages; i++) {
      const page    = await pdf.getPage(i);
      const vp      = page.getViewport({ scale: 1.5 });
      const canvas  = document.createElement('canvas');
      canvas.height = vp.height;
      canvas.width  = vp.width;
      await page.render({ canvasContext: canvas.getContext('2d'), viewport: vp }).promise;
      container.appendChild(canvas);
    }
  }
</script>
```

The viewer page has no download button in the UI. A technically sophisticated user can still access the `/content` endpoint directly or right-click → save on a canvas element. This is **by policy, not by mechanism** — the intent is no accidental download, not cryptographic enforcement.

### §VI.3 — Markdown renderer

`marked.js` (MIT licence) + `DOMPurify` for sanitization. Fetches from `/api/documents/:slug/content`, parses Markdown, sanitizes HTML output, injects into a styled container.

```javascript
const res  = await fetch(`/api/documents/${slug}/content`, { credentials: 'include' });
const text = await res.text();
const html = DOMPurify.sanitize(marked.parse(text));
document.getElementById('content').innerHTML = html;
```

Markdown styles inherit the Borges/Parchment aesthetic: body text in Purple (`#301934`), headers in Mauve (`#915f6d`), emphasis in Wine (`#722f37`).

### §VI.4 — No download UI surface

There is no download button, save link, or share link in the strategia UI. This is intentional. Documents are internal, Cloudflare-Access-gated, and intended for Cam's on-screen review. The viewer is a read surface, not a distribution surface.

## §VII — Document index UI

### §VII.1 — List view

The root route (`/`) renders a filterable list of live documents from `GET /api/documents`. Columns:

| Column | Source |
|---|---|
| Title | `title` |
| Team | `source_team` (badge) |
| Type | `content_type` (icon + label) |
| Size | `byte_size` (human-readable: KB/MB) |
| Date | `created_at` (relative: "3 days ago") |
| Actions | View button; Delete button (Cam-session only, conditionally rendered) |

Filter controls: team selector, content_type selector, date range picker. These pass query parameters to `GET /api/documents`.

### §VII.2 — Conditional delete button

The delete button is rendered only when the UI can confirm the user is operating as Cam (session auth, not a service token). Since service tokens are never used in the browser UI (they are for specialist programmatic access), the delete button is always visible to Cam in practice.

Delete flow: button click → confirmation modal ("Delete '{{title}}'? This cannot be undone.") → confirmed → `DELETE /api/documents/:slug` → list refreshes.

## §VIII — Delete affordance

### §VIII.1 — Hard delete vs. soft delete

**Recommendation: tombstone delete.** The D1 row is retained with `deleted_at` set; the R2 object is purged immediately.

Rationale:

- Audit requirement: Cam needs to be able to confirm a document was deleted and when, especially for CoC briefs and other sensitive materials
- D1 rows are cheap; retaining the metadata skeleton indefinitely has no meaningful cost
- R2 object bytes are freed immediately (cost + privacy benefit)
- The `live_documents` view hides tombstoned rows from all read endpoints without any additional handler logic

This is distinct from a full soft-delete (where the bytes are retained). Bytes are gone; the metadata record of what existed remains.

**Open question Q1** (§XIII): Cam may prefer full hard delete (D1 row also purged). Recommendation is tombstone; Cam decides.

### §VIII.2 — Session-only gate

Service tokens cannot delete. This is enforced at the handler level (`auth.mode !== 'session'` check in §V.5), not only at the scope level. Rationale: a compromised service token should never be able to destroy documents. Only an authenticated Cam browser session can delete.

### §VIII.3 — Audit trail

Every deletion writes an `audit_log` row before the D1 tombstone update and R2 purge. The snapshot field captures the full D1 row state at time of deletion. This means Cam can later query:

```sql
SELECT * FROM audit_log WHERE action = 'DELETE' ORDER BY occurred_at DESC;
```

and see exactly what was deleted, by whom, and when, including the R2 key of the purged object.

## §IX — Ingestion paths

### §IX.1 — Primary: specialist direct POST

The recommended primary ingestion path is specialist-direct POST with a scoped service token.

A specialist (e.g. CoC Scribe) holds a service token scoped to `source_team = 'coc'`. At the end of a session where a brief is produced, the specialist POSTs the document to `POST /api/documents` with the multipart payload. The token's scope prefix is used as `source_team` and enforced by the Worker (token cannot write to a different team prefix).

This is simple, auditable, and requires no additional infrastructure.

**Example specialist upload (curl):**
```bash
curl -X POST https://strategia.skeptou.com/api/documents \
  -H "Authorization: Bearer <coc-service-token>" \
  -F "file=@session-12-brief.md;type=text/markdown" \
  -F "slug=brief-2026-05-14-session-12" \
  -F "title=CoC Session 12 Brief — 2026-05-14" \
  -F "content_type=brief" \
  -F 'tags=["coc","session-12"]'
```

### §IX.2 — Secondary: Cam admin upload

The UI includes an admin upload form (session-only, visible to Cam). This handles documents that are not uploaded by a specialist — e.g. third-party PDFs, manually assembled worksheets, or corrections. `source_team` is set to `cam` for all admin uploads.

The admin form is a simple multipart POST from the browser to `POST /api/documents` using the session cookie.

### §IX.3 — Deferred: agora-auto-publish hook

A webhook-triggered Worker could watch the agora repo for commits to a `reports/<team>/` path and auto-upload the committed file to strategia. This was considered for Phase 1 but is deferred to Phase 3 (open question Q2 in §XIII).

Rationale for deferral: specialist-direct POST is simpler and avoids the agora-webhook-to-strategia pipeline complexity. The agora auto-publish path adds value only if the specialist workflow naturally produces files committed to agora before upload — and that is not the current pattern.

## §X — Auth + scopes

### §X.1 — Auth model

Strategia uses the same `authenticateRequest()` function as phronesis (from `@skeptou/auth-client`, per `specs/auth-core.md`). The function tries session cookie first, then Bearer token. Returns `AuthContext { actor, mode, scope? }`.

```typescript
interface AuthContext {
  actor:  string;                // 'cam' for session; service-token name for Bearer
  mode:   'session' | 'service_token';
  scope?: string;                // token's team prefix, e.g. 'coc'; absent for session auth
}
```

### §X.2 — Service token scopes

Each specialist team gets a service token with a `scope` field stored in the `service_tokens` D1 table (or, if strategia uses a separate D1, a shared auth D1 — open question Q4 in §XIII).

| Token holder | Scope prefix | Can upload | Can read | Can delete |
|---|---|---|---|---|
| CoC Scribe | `coc` | ✓ (to `coc/` prefix only) | ✓ | ✗ |
| SAA Specialist | `saa` | ✓ (to `saa/` prefix only) | ✓ | ✗ |
| Other team specialists | `<team>` | ✓ (to `<team>/` prefix only) | ✓ | ✗ |
| Cam (session) | — | ✓ (to any prefix) | ✓ | ✓ |

Upload scope enforcement in the Worker: the token's `scope` field is used as the `source_team` for the R2 key and D1 row. A `coc`-scoped token cannot produce a row with `source_team = 'saa'`. The Worker does not need to check the slug prefix — it constructs the R2 key from the token scope.

### §X.3 — Service token provisioning

Handled by Cam manually (same as phronesis service tokens). Token is generated (random 32-byte hex), SHA-256 hash stored in the service_tokens table (per auth-core §V.4 model), raw value passed to the specialist one time.

Open question: whether strategia service tokens share the same `service_tokens` table in the phronesis D1, or have their own in the strategia D1 (Q4 in §XIII).

## §XII — Security posture

### §XII.1 — Access gate (non-negotiable)

Cloudflare Access policy must be applied and QA-verified before any document with real content is uploaded. The empty-bucket-first rule from `CLAUDE.md` applies: DevOps deploys empty Access-gated placeholder → QA verifies gating → real content enters.

### §XII.2 — Double-auth

The Access gate (Cloudflare OIDC) handles browser-session identity at the edge. The Worker's `authenticateRequest()` adds a second auth check for the `/api/*` endpoints (session cookie or service token). Service tokens bypass the Access gate — they use Bearer auth directly to the Worker endpoint, which validates the token independently of Access.

This is consistent with the phronesis / auth-core pattern.

### §XII.3 — Content-Security-Policy

The viewer page must include a CSP header that disallows downloads and limits external resource loading. Recommended:

```
Content-Security-Policy: default-src 'self';
  script-src 'self' https://cdnjs.cloudflare.com;
  style-src 'self' 'unsafe-inline';
  img-src 'self' blob:;
  object-src 'none';
  frame-ancestors 'none'
```

`object-src 'none'` explicitly blocks `<object>` and `<embed>` tags that could trigger native PDF handling. `frame-ancestors 'none'` prevents clickjacking.

### §XII.4 — Sensitive document handling

CoC briefs and annotated PDFs may contain sensitive academic, professional, or personal material. The following controls apply:

- `Cache-Control: private, no-store` on all `/content` responses (no CDN caching of document bytes)
- No public sharing links or expiring presigned URLs in Phase 1
- All document access is behind Access gate + Worker auth — no anonymous access path
